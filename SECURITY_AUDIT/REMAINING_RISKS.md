# Remaining risks

These items could not be verified or fixed within this repository, or need a product, infrastructure or credential decision. Each one names the precise action required.

| ID | Risk | Severity | Why it is open | Action required |
|---|---|---|---|---|
| R-1 | On Netlify, the client IP for rate limiting comes from `x-nf-client-connection-ip`. If Netlify ever passed a client-supplied value through, IP limits could be dodged | Medium | Only verifiable on a real Netlify deploy | After the first deploy, send requests with a forged `x-nf-client-connection-ip` and confirm they still share one budget. If not, put Cloudflare in front (`EDGE_SHARED_SECRET`) and rely on `CF-Connecting-IP` |
| R-2 | When Upstash is down, limits are counted per serverless instance, and the backstop is always per instance. A distributed attack can exceed nominal limits across instances | Low | Inherent to a memory fallback | Accept, or add Cloudflare WAF rate-limit rules (see the README's Cloudflare section) |
| R-3 | Revoking a Clerk session does not end it immediately. Networkless JWT checks accept the token until it expires (about 60 s). A deleted user's cached record survives up to 5 minutes if a Redis delete fails | Low | Design trade-off of networkless verification | Accept, or call Clerk's session API for sensitive actions such as account deletion and purchases |
| R-4 | If the Android app does not set `obfuscatedAccountId` on purchases, the first account to verify a token claims it. Since F-01, no token can ever serve two accounts | Low | Depends on app implementation | Make the app always set it, then make it mandatory in production (reject purchases without it) |
| R-5 | After deleting an account, a still-active subscription stays bound to the deleted user, so a new account cannot restore it (409) | Low (product) | Needs a support policy | Decide whether verifying with a new account may move a token away from a *deleted* owner; implement with an audit row |
| R-6 | Retention is not enforced. Soft-deleted notes keep their text; `security_events` (IP addresses), `billing_notifications`, `purchases.raw` and raw provider files are kept indefinitely | Medium (privacy) | Needs a retention policy (legal and product) | Define periods (for example 30 days for deleted notes, 12 months for security events, as long as tax law requires for billing); add a daily purge job |
| R-7 | Google RTDN is authenticated by a shared token in the push URL's query string, which may appear in proxy or platform access logs | Low | Better option needs GCP setup | Switch the Pub/Sub push subscription to OIDC authentication and verify Google-signed JWTs in the webhook |
| R-8 | Notes, collections and collection items have no per-user count limits, only the rate limit (600 requests/min per user) | Low | Product said "unlimited" | Set sane caps (for example 5,000 notes, 200 collections, 500 items each) and add them to `plans.json` |
| R-9 | The storage bucket's access policy (private, least-privilege key, no public listing) cannot be verified from code | Medium | Neon console setting | Confirm in the Neon console that the bucket is private and the key is scoped to that bucket only; rotate it if it was ever shared |
| R-10 | Production Clerk configuration: `CLERK_AUTHORIZED_PARTIES` is a placeholder (`https://your-domain.com`) and `CLERK_WEBHOOK_SIGNING_SECRET` looks like a placeholder in the local `.env` | Medium | Credentials and config | Set real authorized parties (or leave empty for an app with no web client) and the real webhook secret in Netlify |
| R-11 | Dynamic scanning (OWASP ZAP baseline) was not run. The 1.5 GB scanner image was judged unnecessary given the API-level tests; only a deployed instance would add header and TLS checks | Low | No staging deployment exists | Run `docker run -t ghcr.io/zaproxy/zaproxy:stable zap-baseline.py -t https://<staging>/v1/competitions` after deploying |
| R-12 | Branch coverage is below 90% for seven security-critical modules (77–88%) | Low | Remaining branches are defensive fallbacks | See `TEST_COVERAGE.md` for the specific paths |
| R-13 | The real Google Play verifier has only been tested against mocked HTTP | Medium (before launch) | No Play Console listing | Run test purchases (licence testers) through every state before release |
| R-14 | Dev-only advisories in `drizzle-kit` → esbuild (F-22) | Informational | Upgrade path is a breaking `drizzle-kit` change | Re-check when a non-breaking drizzle-kit release drops `@esbuild-kit` |
| R-15 | Account deletion racing with a concurrent write (for example a note created in the same instant) could leave an orphaned private row on a deleted account | Low | Very small window; data stays private | Add `users.status = 'active'` checks to private inserts, or a purge of private rows owned by deleted users in the daily job |
| R-16 | StatsBomb Open Data is not licensed for commercial redistribution (`commercialUseAllowed: false`); `include=raw` returns raw provider JSON to Pro users | Compliance | Licensing | Contract a commercial provider before launch; review whether raw payloads may be shown |
| R-17 | The local `.env` on the developer machine holds production credentials. It is git-ignored, and Gitleaks confirms it was never committed | Low | Operational | Keep it out of shared folders; rotate keys if the machine is lost |
